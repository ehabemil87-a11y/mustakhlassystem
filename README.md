# نظام متابعة المستخلصات — مجموعة الذيابي

نظام ويب لمتابعة المستخلصات المالية من الإدارات (التشغيل والصيانة، النقليات، الطرق،
تأجير المعدات) إلى إدارة الحسابات لإصدار الفواتير، مع دورة مراجعة وإرجاع، وإشعارات
فورية، و**تنبيهات تأخير قابلة للضبط لكل مرحلة**.

النظام **منفصل تماماً** عن نظام «طلبات الصرف» (مشروع Supabase مستقل)، لكنه يحافظ على
نفس الهوية البصرية للمجموعة (خط Cairo، اللون الذهبي `#b8874f`).

> المرجع الشامل للمواصفات في `docs/SPEC.md`.

## الأدوار

| الدور | الصلاحيات |
|---|---|
| موظف إدارة (`department`) | تسجيل مستخلص لإدارته، إرفاق ملفات، رؤية مستخلصات إدارته فقط، إعادة إرسال المرتجع، استيراد مشاريع إدارته |
| موظف حسابات (`accounts`) | رؤية كل المستخلصات، المراجعة، الإرجاع بتعليق إلزامي، رفع الفاتورة |
| أدمن (`admin`) | كل ما سبق + إدارة المستخدمين + إدارة المشاريع + **ضبط تنبيهات التأخير** + التقارير |

الحماية الحقيقية مفروضة على مستوى قاعدة البيانات عبر **RLS**، والمرفقات في bucket خاص
يُوصل إليه عبر **Signed URLs** قصيرة العمر فقط.

## تنبيهات التأخير (الميزة الجديدة)

من تبويب **«تنبيهات التأخير»** في شاشة الأدمن، يُحدَّد عدد الأيام المسموح بها لكل مرحلة:

| المرحلة | المعنى | الافتراضي |
|---|---|---|
| **مراجعة الحسابات** | من وصول المستخلص للحسابات حتى قبوله للتنفيذ | 2 يوم |
| **رفع الفاتورة** | من قبول المستخلص للتنفيذ حتى رفع الفاتورة | 3 أيام |
| **تعديل المرتجع** | من إرجاع المستخلص للإدارة حتى إعادة إرساله | 2 يوم |

بعد تجاوز المدة:
- يظهر المستخلص بشارة **«متأخر (N يوم)»** في الجداول ولوحة المؤشرات.
- تُنشأ تلقائياً (كل ساعة عبر pg_cron) **إشعارات تأخير** توجَّه للجهة المسؤولة
  (الحسابات لمرحلتي المراجعة والفاتورة، والإدارة صاحبة المستخلص لمرحلة المرتجع).

القيمة `0` لأي مرحلة تعطّل تنبيهها، ومفتاح التفعيل العام يوقف كل التنبيهات.

## دورة العمل الشهرية (استيراد مستخلصات دفعة واحدة)

أول الشهر يمكن لموظف الإدارة إنشاء مستخلصات إدارته دفعة واحدة بدل إدخالها فرداً فرداً:

1. **تبويب «استيراد مستخلصات»** → اختر الفترة (الشهر) → ارفع ملف Excel بالأعمدة:

   | project | amount | notes |
   |---|---|---|
   | مشروع طريق الملك فهد | 125000 | مستخلص أغسطس |
   | صيانة مبنى الإدارة | 48000 | |

   - `project` = اسم المشروع **مطابقاً تماماً** لما في تبويب المشاريع (أو استخدم عمود `code` بكود المشروع) — إلزامي.
   - `amount` = قيمة المستخلص — إلزامي (رقم أكبر من صفر).
   - `notes` = ملاحظات — اختياري.
2. تظهر معاينة توضّح الصفوف «الجاهزة» وغير المطابقة → اضغط **«إنشاء N مستخلص»**.
   تُنشأ كلها بحالة «قيد المراجعة» بأرقام تلقائية (`OPS-2026-001` …).
3. بعدها ادخل على كل مستخلص من الجدول → قسم المرفقات → **«＋ إضافة مرفقات لهذا المستخلص»** لرفع ملفاته.

> المستخلص الفردي ما زال متاحاً عبر زر **«مستخلص جديد»** (مع مرفقاته في نفس الخطوة).

## تغيير كلمات المرور

- **كل مستخدم:** زر **«تغيير كلمة المرور»** في الشريط العلوي (يغيّر كلمته بنفسه).
- **الأدمن:** زر **«كلمة المرور»** بجانب كل مستخدم في تبويب «المستخدمون» لإعادة التعيين
  (عبر Edge Function آمنة `admin-set-password`).

## تحديثات (ملاحظات المدير العام)

- **المدير العام (دور جديد):** تبويب **«لوحة المعلومات»** — كروت مؤشرات بالأعلى ورسوم بيانية بالأسفل
  (حسب الحالة/الإدارة/الشهر + القيمة)، مع **فلتر بالشهور**، وصلاحية **قراءة فقط** لكل البيانات.
- **متابعة زمنية بارزة:** عمود **«منذ»** في جدول المستخلصات يُظهر من الخارج كم بقي كل مستخلص في مرحلته
  (مثل «منذ 3 أيام») دون فتحه، وسجل الحركات يعرض مدة كل خطوة.
- **سبب التأخير الإلزامي:** عند تنفيذ أي إجراء على مستخلص تجاوز مدته، يجب كتابة سبب التأخير ويُسجَّل في السجل.
- **رقم الدفعة:** حقل جديد في المستخلص (يدوي وفي الاستيراد).
- **أنواع المرفقات:** مستخلص عمالة / مستخلص / مستخلص المستهلكات ومقاولي الباطن / مستخلص مستهلكات كهرباء وميكانيكا / أخرى.
- **تحميل كل المرفقات** دفعة واحدة من شاشة التفاصيل.
- **إضافة مشروع منفرد** بزر (اسم + إدارة، الحالة «نشط» تلقائياً) — دون الحاجة لملف Excel.
- **استيراد المشاريع:** عمود `code` أُلغي؛ الأعمدة الآن **`name`** + **`department`** (لملف يشمل كل الإدارات).
- **استيراد المستخلصات:** الأعمدة **`project` / `amount` / `month` / `payment_number` / `notes`**، مع معاينة، ثم إضافة المرفقات لكل صف.

## إعادة الإنشاء على مشروع Supabase جديد (عند الحاجة)

1. أنشئ مشروع Supabase جديداً واحفظ `SUPABASE_URL` و`anon key`.
2. في SQL Editor نفّذ بالترتيب: `01 → 02 → 03 → 04 → 05`.
3. أنشئ أول أدمن من Supabase Auth ثم أضف صفه في `profiles` (انظر تعليق نهاية `04`).
4. انشر الدالة: `supabase functions deploy create-user`
   واضبط السر `INTERNAL_EMAIL_DOMAIN` (وإلا يُستخدم الافتراضي `mustakhlas.internal`).
5. حدّث `SUPABASE_URL` و`SUPABASE_ANON_KEY` و`INTERNAL_EMAIL_DOMAIN` أعلى `<script>` في `index.html`.
6. ارفع على GitHub وفعّل GitHub Pages (Branch: main، Folder: root).
